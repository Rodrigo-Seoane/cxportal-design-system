## Overview

Instance Card is a compact row used to list a single org instance — typically inside a scrollable "Instances" panel, grouped by category. Each card shows the instance name and a drag handle for reordering, and can optionally lead with a checkbox for multi-select bulk actions.

## When to use

**Use Instance Card for:**

- Listing org instances inside a group in the Roles/Users detail sidebar panel
- Letting a user drag-reorder instances within or across groups
- Multi-select bulk actions across instances (Clickable interaction)
- A read-only, non-selectable instance reference (Read Only interaction)

**Do not use for:**

- General-purpose list items unrelated to instances — use Vertical Tab or Table Row instead
- Free-form tag or filter selection — use Chips
- Single-select tab navigation without drag reordering — use Vertical Tab

## Anatomy

- **Checkbox** (Clickable only) — 16×16px multi-select control, ticked when the card is Active or Multi Select
- **Card** — bordered container with the instance title and a drag handle
  - **Title** — instance name, semibold, 12px, truncates with ellipsis
  - **Drag handle** — `DotsSixVertical` icon, 12×12px, signals the row can be reordered

## Accessibility

- The card itself is `role="button"` with `tabIndex`, `Enter`/`Space` activation, and `aria-pressed` reflecting selection
- Disabled cards drop `role`/`tabIndex` and set `aria-disabled`
- The checkbox uses the same accessible native `<input type="checkbox">` as the standalone Checkbox component
- The drag handle icon is `aria-hidden` — it is a visual affordance only; actual reordering must be wired through a real drag-and-drop implementation (not built here)

<DosDonts>
  <Do description="Use Clickable when the list supports multi-select bulk actions; use Read Only for a static reference list with no selection." />
  <Dont description="Combine Active and Multi Select on the same card — they're mutually exclusive states in Figma, not a state you can stack." />
</DosDonts>

## Code

### Clickable, default

```tsx
import { InstanceCard } from '@/components/ui/instance-card'

<InstanceCard title="qa-cft-testing" />
```

### Multi-select checked

```tsx
<InstanceCard title="qa-cft-testing" state="multi-select" onCheckedChange={(checked) => {}} />
```

### Read only

```tsx
<InstanceCard title="qa-cft-testing" interaction="read-only" />
```

### Props

```tsx
type InstanceCardState = 'default' | 'active' | 'multi-select' | 'disabled'
type InstanceCardInteraction = 'clickable' | 'read-only'

interface InstanceCardProps {
  title?: string                         // default: 'qa-cft-testing'
  state?: InstanceCardState              // default: 'default' — Hover is derived internally
  interaction?: InstanceCardInteraction  // default: 'clickable'
  onClick?: () => void
  onCheckedChange?: (checked: boolean) => void
  className?: string
}
```

## Open Questions

- **Default/Disabled border values still don't match Figma's pulled hex.** Figma's Default/Disabled secondary border colors (`#aab0b8`, `#eff1f3`) don't correspond to any existing `--border-color-surface-active-secondary-*` token value in this codebase — those resolve to `#adadad` and `#d2e0c8` respectively, and neither exists under any other token name either. Needs a designer call before touching the shared token values, given the blast radius (`Button`/`Checkbox`'s `Radio` already consume the same tokens).
  **Correction (2026-09-10):** the Hover value was previously flagged here too (`#7a828c` from the component pull vs. `#8d8d8d` from `--neutral-400`) and repointed globally on that assumption — wrong call. A direct Figma Variables export confirms `Neutral/400` is `#8d8d8d` in both brand modes; the `#7a828c` seen in the earlier component pull was a stale or locally-overridden fallback, not the true bound variable. `--neutral-400` has been reverted to `#8d8d8d`, and the Hover row above now matches without a designer call needed.
- **Read Only still shows the drag handle.** A card that can't be selected or reordered (no checkbox) still renders the `DotsSixVertical` drag-handle icon in Figma. Implemented faithfully, but this reads as a real contradiction — a drag affordance implies drag capability, which "Read Only" explicitly denies. Needs a designer call.
- **Drag-reorder itself isn't implemented.** The design shows a drag handle, but no drag-and-drop behavior is specified or built — only the visual affordance exists.
