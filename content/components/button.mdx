## Overview

Buttons allow users to take actions and make choices with a single tap. They communicate actions that users can take and are typically placed throughout the UI, in places like dialogs, modal windows, forms, cards and toolbars.

## When to use

- To trigger an action or event, such as submitting a form, opening a dialog, canceling an action, or performing a delete operation
- To navigate users to a new page or section
- To confirm or dismiss information in dialogs and modals

## Anatomy

The Button component consists of:

- **Container** — Background with border and border-radius
- **Label** — Action text describing what the button does
- **Icon (optional)** — Visual symbol reinforcing the action (left position)
- **States** — Visual feedback for default, hover, active, and disabled interactions

**Colored Background** and **Destructive** are standalone variants for specific usage contexts — colored surfaces and irreversible actions respectively. They are detailed in the sections below.

### Colored Background state

The `colored-bg` variant is for buttons placed on non-white surfaces — blue action bars, colored page headers, hero banners, or highlighted cards. The default white fill and blue border maintain clear button affordance against colored backgrounds while adapting to the surface context.

**Color spec:**

| State | Background | Border | Text |
|---|---|---|---|
| Default | Neutral/0 `#ffffff` | Primary `#689df6` | On Action/Transparent `#3264b8` |
| Hover | Surface/Action/Hover `#689df6` | `#689df6` | On Action/Primary `#eff1f3` |
| Active | Neutral/50 `#f8f8f8` | Border/Secondary `#aab0b8` | On Action/Transparent `#3264b8` |
| Disabled | Surface/Disabled `#eff1f3` | Border/Disabled `#d9dce0` | Text/Disabled `#aab0b8` |

<DosDonts>
  <Do description="Use colored-bg buttons on non-white surfaces — blue banners, colored cards, tinted page headers — where default button tokens would blend into the background." />
  <Dont description="Use colored-bg buttons on white or neutral backgrounds. On white, use the default Primary, Secondary, or Form Controls variants instead." />
</DosDonts>

### Destructive state

The Destructive state signals to users that the action they are about to confirm **cannot be undone**. It applies to all four variant types, each with its own red-toned treatment:

- **Primary destructive** — Solid dark red fill. Used in Modals/Dialogs as the confirm button for the destructive action.
- **Secondary destructive** — Pink/rose outline with red text. Used as the paired cancel-style button when an explicit red secondary is needed.
- **Form Controls destructive** — Dark red fill. Used for inline async destructive controls.
- **Text destructive** — Red text only. Used for low-prominence destructive links.

**Color spec — Destructive (DS Error ramp):**

| State | Background | Border | Text |
|---|---|---|---|
| Default | Error/500 `#ab0c36` | Error/600 `#690821` | On Action/Primary `#eff1f3` |
| Hover | Error/300 `#f3547d` | Error/200 `#f792ac` | On Action/Secondary `#021920` |
| Active | Error/500 `#ab0c36` | Error/600 `#690821` | On Action/Primary `#eff1f3` |
| Disabled | Surface/Disabled `#eff1f3` | Border/Disabled `#d9dce0` | Text/Disabled `#aab0b8` |
| Focus ring | — | — | Error/500 `#ab0c36` / 50% |

> **Why does hover reverse to light pink?** `#f3547d` (Error/300) with dark `#021920` text meets WCAG AA. The darker Error/500 default with light text also passes. Reversing on hover makes the interaction feel responsive without breaking contrast at either state.

**Usage rules:**
- Use exclusively in Modals and Dialogs — never as a standalone page action.
- Always pair with a secondary/cancel button so the user has an explicit escape.
- The button label must describe the destructive action specifically: **"Delete Campaign"**, not just "Delete". **"Remove Member"**, not just "Remove".
- Never use Destructive as the sole button in a dialog — that removes the escape hatch.

  <Do description="Label the button with the specific resource being destroyed — 'Delete Article', 'Remove Member', 'Revoke Access'. Specificity reduces accidental clicks." />
  <Dont description="Use the Destructive state for reversible actions (archive, deactivate, hide). Those belong on a Form Controls or Secondary button." />
</DosDonts>

<DosDonts>
  <Do description="Use destructive buttons only for irreversible actions inside modals — deleting a resource, revoking access, permanently removing data." />
  <Dont description="Use destructive buttons for cancellation or navigation. Those actions belong on a Secondary or Text button." />

### Icon-only buttons

Icon-only buttons use square sizes: **Icon Regular (48×48)**, **Icon Small (36×36)**, **Icon XS (24×24)**. They follow the same variant rules but require an `aria-label` since there is no visible label.

## Principles for use

### Design principals

- **Icons are used on the Left** — When buttons include icons, position them to the left of the label text to maintain visual scanning order and reinforce the action meaning.
- **Guide users to achieve the desired actions** — Use visual hierarchy through button types and styles to direct users toward primary objectives while making secondary options accessible.
- **Prevent user to make mistakes** — Use appropriate button types and states to communicate availability and consequences, reducing the risk of unintended actions.

## Button Group

When multiple buttons form a group, align them in **one line with gaps between them**. Never place buttons flush against each other — a gapless group is visually indistinguishable from a Toggle Button and creates ambiguity for users.

## Code

### Basic usage

```tsx
import { Button } from '@/components/ui/button'

<Button variant="primary" size="regular">
  Save changes
</Button>
```

### With icon

```tsx
import { Button } from '@/components/ui/button'
import { Plus } from 'lucide-react'

// Icon left (most common)
<Button variant="primary" size="sm">
  <Plus />
  Add item
</Button>

// Icon right
<Button variant="secondary" size="sm">
  Next step
  <ArrowRight />
</Button>
```

### Icon-only

```tsx
import { Button } from '@/components/ui/button'
import { Trash } from 'lucide-react'

<Button variant="form-controls" size="icon-sm" aria-label="Delete row">
  <Trash />
</Button>
```

### Disabled state

```tsx
<Button variant="primary" disabled>
  Saving…
</Button>
```

### Destructive button

```tsx
// Always pair with a cancel button — never use alone
<div className="flex gap-2 justify-end">
  <Button variant="secondary" size="sm">Cancel</Button>
  <Button variant="destructive" size="sm">
    Delete Campaign
  </Button>
</div>
```

### Colored background button

```tsx
// Always render colored-bg inside a non-white surface
<div className="bg-[#4285f4] p-6 rounded-lg">
  <Button variant="colored-bg" size="sm">Get Started</Button>
</div>
```

## Accessibility

- All buttons must have accessible labels — visible text or `aria-label` for icon-only buttons
- Ensure sufficient color contrast (minimum **4.5:1** for text against background)
- Disabled buttons should remain perceivable but clearly indicate unavailability — do not hide them
- Focus states must be visible for keyboard navigation (the component ships with a `focus-visible` ring)
- Icon-only buttons require a tooltip or `aria-label` to communicate their purpose to assistive technology
