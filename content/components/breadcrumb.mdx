## Overview

Breadcrumbs render the user's current position within the application hierarchy as a left-to-right trail of links separated by caret icons. The trail always begins with a `HouseIcon` (the module root) and ends with the current page label in semibold — every item before it is a real navigation link. Six depth variants (01–05 plus Max) cover real navigation hierarchies in the product. The Max variant introduces ellipsis truncation for paths deeper than 5 levels.

Breadcrumbs were previously deprecated in CxPortal; they are being re-introduced as a first-class DS component to support deeper navigation hierarchies introduced in the Campaigns Email and Knowledge Management modules. **Migrated (2026-09-10):** the app's 7 real inline breadcrumb call sites (Access Management's 3 detail pages, WFM Reporting's 4 pages) now use this component. 8 remaining call sites inside `app/sandbox/campaigns-email/` and `app/sandbox/collapsible-filter/` are still hand-rolled — a separate prototype subsystem with its own styling convention, tracked in `Open_Questions.md` rather than migrated here.

## When to use

- On any page that is two or more levels deep in the navigation hierarchy (i.e. below a top-level section).
- Above the `PageTitle` component, at the very top of the content area.
- When the sidebar alone doesn't convey position — e.g. a page reachable through multiple parent paths.

## When not to use

- Do not use breadcrumbs on top-level pages — there is nothing to navigate up to.
- Do not use breadcrumbs as a replacement for tab navigation within a single page — use the Tab Group component instead.
- Do not nest beyond the Max variant's capacity. If the trail would exceed the ellipsis truncation pattern, the information architecture needs rethinking.

## Anatomy

- **Home icon** — `HouseIcon` (14×14), always the first item, always a link to `homeHref`.
- **Caret separator** — `CaretRightIcon` (12×12) between each item. Decorative, `aria-hidden="true"`.
- **Ancestor labels** — Body/Small Regular (12 px, 400 weight). Each is a link.
- **Current page label** — Body/Small SemiBold (12 px, 600 weight, 0.24px letter-spacing). Not a link — represents where the user is.
- **Ellipsis (Max variant only)** — A "…" text node replacing hidden middle ancestors. Displayed when the trail exceeds 5 levels. Not a link.

All labels use `--text-on-action-transparent` (`#3a8015`).

## Guidelines

### DOs

- Always position breadcrumbs above the `PageTitle` — they are a navigation aid, not a heading element.
- Use the depth that matches the actual page hierarchy — don't pad `items` with placeholder levels.
- Keep ancestor labels to the actual page/resource name — no generic labels like "Back" or "Parent".
- Give every item except the last one an `href` — that's what makes it a real navigation link.

### DON'Ts

- Don't nest beyond the Max variant's capacity. If the trail would exceed the ellipsis truncation pattern, the information architecture needs rethinking.
- Don't use the deprecated Breadcrumb Deprecated component (slash separators, different typography) for new screens.

## Code

### Props

```tsx
interface BreadcrumbItem {
  /** Label text. The last item in the array is treated as the current page. */
  label: string
  /** Destination for this item. Omit only on the last (current-page) item. */
  href?: string
}

interface BreadcrumbProps {
  /** Ancestor + current page trail. 1–5 items shown in full; beyond 5 the Max variant truncates middle ancestors with an ellipsis. */
  items: BreadcrumbItem[]
  /** Destination for the leading Home icon (the module root). */
  homeHref: string
  className?: string
}
```

### Usage examples

```tsx
import { Breadcrumb } from '@/components/ui/breadcrumbs'

{/* 1 level — current page only */}
<Breadcrumb
  homeHref="/accounts"
  items={[{ label: 'Social Security Admin' }]}
/>

{/* 2 levels — account level */}
<Breadcrumb
  homeHref="/accounts"
  items={[
    { label: 'Social Security Admin', href: '/accounts/ssa' },
    { label: 'Benefit Status Updates' },
  ]}
/>

{/* 4 levels — topic / item level */}
<Breadcrumb
  homeHref="/campaigns"
  items={[
    { label: 'Campaigns', href: '/campaigns' },
    { label: 'User Lists', href: '/campaigns/lists' },
    { label: 'Retirees Q4', href: '/campaigns/lists/retirees-q4' },
    { label: 'Retirement Planning Reminders' },
  ]}
/>
```

## Accessibility

- The trail is a `<nav aria-label="Breadcrumb">` wrapping an `<ol>`, each item an `<li>` — this gives screen readers the "list, N items" / "position X of N" announcements.
- The Home icon's link carries `aria-label="Home"`.
- `CaretRightIcon` separators carry `aria-hidden="true"` — never rendered as literal `/` or `›` characters.
- Ancestor items are real `next/link` anchors. The current page item is a `<span>` with `aria-current="page"`, not a link.
- The 12 px label size meets the WCAG-recommended minimum for body text. Ensure sufficient contrast of #3a8015 on the page background at all expected surface colors.
