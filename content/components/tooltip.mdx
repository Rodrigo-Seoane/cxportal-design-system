## Overview

This page ships two related components. Both surface secondary context anchored to a trigger element.

**Tooltip** carries short explanatory text shown on hover or focus, and dismisses automatically when the pointer or focus moves away.

**Dismissible Tip** carries longer content with a title, body, and explicit close control — used for complex explanations or first-time-user onboarding hints.

## Design principles

**Tooltip is transient, Dismissible Tip is persistent.** Tooltip appears on hover or focus and disappears as soon as the trigger loses attention. Dismissible Tip stays until the user closes it, so it can carry content that requires reading time.

**User-triggered, not system-triggered.** Both appear because the user pointed at, focused on, or opened something. Neither is used to broadcast events — that is what Toast Notifications and Message Box are for.

**Content length dictates the choice.** Tooltip is capped at roughly 80 characters, a single short sentence with no title. Dismissible Tip carries a title plus a body up to roughly 500 characters. Beyond that, the interaction belongs in a Modal or Side Panel.

**Anchor before position.** Both attach to a specific element with an 8px gap. Tooltip supports four placements so the position adapts to viewport edges. Dismissible Tip is always positioned above its trigger, flipping below only when there is no space above.

## When to use

- **Tooltip** — to explain an icon button or unlabeled control whose action is not obvious from the glyph alone.
- **Tooltip** — to give short format examples or constraints on form inputs.
- **Tooltip** — to disambiguate truncated text on tight rows without expanding row height.
- **Dismissible Tip** — to introduce a new feature on first use.
- **Dismissible Tip** — to explain a complex or destructive action before the user commits.
- **Dismissible Tip** — to surface content needing 5–20 seconds of reading time.

## When not to use

- Don't put essential information in either component. Both are supplementary — required information must be visible without user action.
- Don't use Tooltip for content longer than 80 characters. Use Dismissible Tip or an inline description.
- Don't use either for system events, errors, or notifications. Use Toast Notifications or Message Box.
- Don't nest a Tooltip inside a Dismissible Tip or vice versa — nested transient UI creates unresolvable focus and dismiss ambiguity.
- Don't stack multiple tooltips or tips in the same view. If several are needed at once, the design has an information density problem.
- Don't use either to replace form field or button labels. Labels must always be visible.
- Don't use Tooltip on touch-only surfaces without a tap-to-toggle alternative — there is no hover on touch.

## Anatomy

**Tooltip container.** 8px padding, 4px radius, 1px border, single content row, no title. Max-width 320px; content wraps at that width. Anchored to its trigger with an 8px gap on the placement side.

**Beak.** Only Tooltip has one — an 8×8 square rotated 45°, with the two outer-facing border edges visible so it reads as a triangle pointing at the trigger. The placement controls which edge it sits on.

**Dismissible Tip container.** 16px top and side padding, 24px bottom, 8px radius, 0.5px border, 16px gap between the header row and the body. Two stacked text nodes plus a 12×12 close control aligned right in the header row. No beak — vertical alignment communicates the anchor.

**Content text.** Tooltip: 12px Regular at 20px line-height. Dismissible Tip: 10px SemiBold title and 10px Regular body, both at 16px line-height.

Both components carry the same shadow — `0 4px 12px rgba(5, 3, 38, 0.08)`, from the Figma "Tooltip Shadow" effect. The trigger gap is 8px in every direction. Tooltip opens after 300ms and closes after 150ms.

## Placement

Tooltip supports `top`, `right`, `bottom`, and `left`. Pick the placement that fits the available space: if the trigger is near the viewport top, use `bottom`; near the right edge, use `left`.

## Accessibility

The tooltip carries `role="tooltip"` and a generated id, and the trigger element receives `aria-describedby` pointing at it, so screen readers announce the trigger's name plus the tooltip content when focus lands.

Tooltip opens on **both hover and keyboard focus** — hover-only would fail WCAG 2.1.1. The open delay applies equally to focus.

It is **hoverable, dismissable, and persistent** per WCAG 1.4.13: the pointer can move onto the tooltip surface without closing it, `Escape` dismisses it while focus stays on the trigger, and it otherwise stays open until hover or focus leaves.

Dismissible Tip carries `role="dialog"` labelled by its title, and the close control is a real `<button>` with an accessible name.

On the dark theme, verify text contrast meets WCAG 1.4.3 AA — 4.5:1 for normal text against the dark surface.

## Code

### Basic usage

```tsx
<Tooltip content="Duplicate this campaign">
  <Button variant="secondary" size="icon-sm" aria-label="Duplicate">
    <Copy />
  </Button>
</Tooltip>
```

### Placement and theme

```tsx
<Tooltip content="Appears below the trigger" placement="bottom" theme="dark">
  <Button variant="secondary">Hover me</Button>
</Tooltip>
```

### Dismissible Tip

```tsx
<DismissibleTip
  title="Permission Roles"
  content="This Entity contains Items that reference this field so it cannot be deleted."
  type="secondary"
  onDismiss={() => setTipSeen(true)}
/>
```

## Notes on the Figma source

Tooltip is `694-13794`; Dismissible Tip is `3210-1866`. Values above come from the component variants rather than the Principles (`3215-514`) or Usage (`3215-515`) frames, which diverge in three places: the Usage token table caps Tooltip at 300px where the component uses 320px, describes the close control as 16×16 where the component draws 12×12, and lists `Icon/Body/Primary #021920` for tooltip text where the component uses `Text/Body/Primary #1d1d1d` — a token name and value that both predate the rebrand.

Three Figma-side defects are outstanding. The Dismissible Tip `theme` property has no visual effect on either type — container, title, and body are all keyed on `type` alone, so Dark and Light render identically; the code omits the prop rather than expose a no-op. The Secondary + Dark variant's body text is a hardcoded literal instead of being bound to the `cardContent` property. And the same component uses four different container widths: 300px and 281px in the component set, 274px and 257px in the Usage frame's own demo instances.
