## Overview

Inline Stats Cards are compact analytics tiles designed to appear inline within detail pages — not as standalone executive dashboards. Each tile shows a label and a formatted value side by side, and a row groups 3–5 tiles horizontally, sharing the available width equally. They're used inside Account, Campaign Group, and Topic detail views to surface key counts and rates at a glance without leaving the page context.

Distinct from [Stats Cards](/components/stats-cards) (dashboard KPI cards with a category icon, used standalone on index pages and dashboards) — Inline Stats Cards have no icon and no trend indicator. They're intentionally minimal, optimised for scanning rather than deep analysis.

## When to use

- Inside a detail page (Account, Campaign Group, Topic), directly below the title and breadcrumb, where a handful of summary KPIs help orient the user before they scroll into tables and charts
- When the metrics are counts or rates — not trends or time-series that need a chart
- When you need 3–5 metrics in a single horizontal row without vertical stacking

**Do not use** for dashboard-level KPI cards — use [Stats Cards](/components/stats-cards), which includes a category icon and is designed for standalone card grids. Do not use when the metric needs a sparkline or trend indicator. Do not use for a single isolated metric — a plain text label is sufficient.

## Anatomy

- **Inline Stats Row** — A horizontal flex container holding 3–5 tile children with an 8px gap, on a light gray background (`--surface-section-group-bg`). Tiles share available width equally.
- **Inline Stat Tile** — A single tile with two elements side by side: the label (left, semibold, primary text color) and the value (right, light weight, primary text color). White background, 4px radius, `15px 10px` padding.
- **Label** — Descriptive text identifying the metric (e.g. "Campaign Groups", "Topics"). 12px semibold.
- **Value** — The metric's pre-formatted value string (e.g. "48,5", "24"). 14px, light weight (300) — deliberately lighter than the label, not bold.
- **Unit** *(optional)* — A trailing glyph after the value (`%`, `€`, `$`, `k`, `M`, `kb`, `ms`, `s`), 10px, light weight, secondary text color.

## Do's & Don'ts

<DosDonts>
  <Do description="Always use the Inline Stats Row container — never place tiles directly on the page without the row wrapper. Keep tile count between 3 and 5 per row." />
  <Dont description="Go below 3 or above 5 tiles in a row. Fewer than 3 looks sparse; more than 5 becomes unreadable at common viewport widths." />
</DosDonts>

<DosDonts>
  <Do description="Place the row immediately below the entity title and breadcrumb, before tables or tab content, to anchor the summary at the top of the detail view." />
  <Dont description="Set fixed widths on individual tiles. The row distributes space equally across whatever tiles are present." />
</DosDonts>

<DosDonts>
  <Do description="Use consistent formatting within a row. If most tiles show counts, keep the odd rate-based tile in the same row or move it to a separate row instead." />
  <Dont description="Mix Inline Stats Cards with Stats Cards in the same row. They serve different contexts and have different visual weights." />
</DosDonts>

## Code

### Basic usage

```tsx
import { InlineStatTile, InlineStatsRow } from '@/components/ui/inline-stats'

<InlineStatsRow>
  <InlineStatTile label="Campaign Groups" value="11" />
  <InlineStatTile label="Topics" value="4" />
  <InlineStatTile label="Lists" value="4" />
  <InlineStatTile label="Templates" value="2" />
  <InlineStatTile label="Campaigns" value="14" />
</InlineStatsRow>
```

### With units

```tsx
<InlineStatsRow>
  <InlineStatTile label="Subscribers" value="678" />
  <InlineStatTile label="Active Campaigns" value="4" />
  <InlineStatTile label="Open Rate" value="61,5" unit="percent" />
  <InlineStatTile label="Delivery Rate" value="78,4" unit="percent" />
</InlineStatsRow>
```

## Accessibility

- The row renders with `role="list"` and each tile with `role="listitem"` so assistive technology can announce the tile count and navigate between them.
- Labels and values are adjacent text nodes within each tile, which screen readers parse naturally as an associated pair without needing extra ARIA wiring.
- No color-only signal is used anywhere in this component — there's no trend/delta indicator to begin with.

## Open questions

- **This doc previously described an entirely different, unrelated component.** Before this pass, this page documented a fictional `MetricTile` API with sparklines, signed deltas, and `format="currency"|"percent"|"number"` smart-formatting (K/M abbreviation, `$X,XXX` currency, etc.) — none of which has any backing in the actual Figma "Inline Cards" / "Inline Stats Row" component nodes, which are a dead-simple label + value + optional unit-glyph pair with no icon, no sparkline, no delta, and no format-conversion logic at all. The previous doc's own Code samples imported from `@/app/sandbox/campaigns-email/_components/MetricTile` — a real, separate sandbox prototype in this codebase, but not the DS component this page is supposed to document. That sandbox component was not touched by this pass; it's a distinct, feature-specific prototype, out of scope here.
- **Figma's own Usage doc (`2297-4741`) describes that same fictional richer API** — sparklines, deltas, `aria-label` with unabbreviated numbers, a token table with pre-rebrand-blue values (`#4285f4` for a "sparkline stroke color" that doesn't exist) — none of which matches the real pulled components either. Figma's own Principles doc (`2297-4845`) is more accurate: it explicitly says "MetricTile has no icon, no sparkline in the current implementation." Built to match the real components per the standing "component wins" rule; Usage's speculative Code/Token sections were not implemented.
- **The 5-tile row instance breaks its own equal-distribution rule.** Figma's 3-tile and 4-tile "Inline Stats Row" instances give every tile `flex-1` (equal width), matching Principles' explicit "auto-layout with equal distribution" anatomy rule. The 5-tile instance instead fixes the first tile's width (`shrink-0`) while the other four stay `flex-1` — an inconsistency with its own sibling variants and the written rule. Treated as a Figma authoring slip; built with equal distribution for all tile counts.
- **Kilobyte and Millisecond units are rendered as text, not Figma's baked icon assets.** Both are tiny (9×9px) flattened SVGs in Figma with no readable path data worth extracting; rendered as "kb"/"ms" text abbreviations instead, consistent with the other 6 unit types (which are already plain text glyphs).
