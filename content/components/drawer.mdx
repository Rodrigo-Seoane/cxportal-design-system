## Overview

The Drawer is a 520 px panel pinned to the right edge of the viewport. It slides in to surface record detail, contextual actions, or a focused form while the user keeps their place on the page underneath.

Unlike Modal, Drawer ships **unopinionated about blocking**. It renders no backdrop, no focus trap, and no body-scroll lock. Whether the panel interrupts the page or sits alongside it is a decision the consuming page makes, not the component:

- **DFC pattern** — non-blocking. Render the Drawer as-is. The page stays interactive and the user can keep navigating while the panel is open.
- **ACGR pattern** — blocking. The page supplies its own backdrop, marks the app shell `inert`, and traps focus. See Modal's app-shell-isolation effect for the reference implementation.

This split is deliberate. A component that guessed wrong would either trap focus in a panel the user is meant to work around, or leave a genuinely modal panel keyboard-escapable into dead page content.

---

## When to use

- Showing detail for a selected row without losing the list context behind it.
- A form or focused flow tied to the current page that should be dismissible.
- Content too large for a Modal but not substantial enough to justify its own route.
- Any case where the user benefits from referencing the page while working in the panel.

**Do not use a Drawer when:**

- A short confirmation is all that's needed — use `Modal`.
- The content is top-level navigation — use the sidebar.
- You would be stacking one Drawer inside another. Open a Modal from within the Drawer instead.

---

## Anatomy

- **Panel** — 520 px wide, full viewport height, pinned right. No corner radius. Drop shadow `-4px 0 24px rgba(5, 3, 38, 0.08)` ("Drawer Shadow" in Figma).
- **DrawerHeader** — min-height 80 px. Holds the title, an optional description line, an optional record ID, and the × close button. Separated from the body by a 1 px internal border.
- **DrawerBody** — the scrollable region. Padding 16 px, `overflow-y: auto`.
- **DrawerFooter** — min-height 72 px. Left-aligned action row, separated from the body by a 1 px internal border. Optional — the No Footer variant omits it entirely.

---

## Do's & Don'ts

### DOs

- Always give the Drawer an accessible name — either a visible `DrawerHeader` title (wired automatically) or an `aria-label`.
- Always render the × close button. Users expect both `Esc` and a visible affordance.
- Keep footer actions **left-aligned**. Cancel leftmost, primary action to its right. No DS footer right-aligns its button group.
- Put every action in the `DrawerFooter`. Primary and destructive actions never live in the scrollable body.
- Use `size="sm"` buttons in the footer — that is what Figma specs.
- Pair the header and footer `variant`.

### DON'Ts

- Don't right-align or `justify-content: flex-end` the footer. This is the single most common drift on this component.
- Don't stack Drawers. Open a Modal from inside one instead.
- Don't change route when the Drawer closes — it is a layer over the current route.
- Don't put route-changing tabs inside a Drawer.
- Don't let body content overflow horizontally. Design for the fixed 520 px width.
- Don't add a corner radius to the panel. Figma specs none.

## Code

### DFC — non-blocking record detail

```tsx
import { Drawer, DrawerHeader, DrawerBody, DrawerFooter } from '@/components/ui/drawer'
import { Button } from '@/components/ui/button'

const [open, setOpen] = useState(false)

<Drawer open={open} onClose={() => setOpen(false)}>
  <DrawerHeader
    variant="compact"
    itemId="item_01kaajp2924m0z8qn26bhja22f"
    description="Created Jan 30, 2026, 03:10 PM"
    onClose={() => setOpen(false)}
  >
    DE Delaware First Health Holidays
  </DrawerHeader>

  <DrawerBody>{/* detail content */}</DrawerBody>

  <DrawerFooter variant="compact">
    <Button variant="text" size="sm">Cancel</Button>
    <Button variant="primary" size="sm">Save</Button>
  </DrawerFooter>
</Drawer>
```

### ACGR — blocking, page supplies the backdrop

```tsx
{open && (
  <div
    role="presentation"
    onClick={() => setOpen(false)}
    style={{ position: 'fixed', inset: 0, zIndex: 39, background: 'var(--surface-overlay)' }}
  />
)}

<Drawer open={open} onClose={() => setOpen(false)}>
  <DrawerHeader
    description="Click a variable to insert at cursor."
    onClose={() => setOpen(false)}
  >
    Variables
  </DrawerHeader>

  <DrawerBody>{/* variable list */}</DrawerBody>

  <DrawerFooter>
    <Button variant="text" size="sm">Cancel</Button>
    <Button variant="secondary" size="sm">Review Impact</Button>
    <Button variant="primary" size="sm">Proceed with Failover</Button>
  </DrawerFooter>
</Drawer>
```

The page owning a blocking Drawer is responsible for the backdrop, marking the app shell `inert` or `aria-hidden`, and trapping focus. Drawer does none of this, because it cannot know which pattern it is being used in.

### No footer — read-only panel

```tsx
<Drawer open={open} onClose={() => setOpen(false)}>
  <DrawerHeader onClose={() => setOpen(false)}>Activity Log</DrawerHeader>
  <DrawerBody>{/* read-only content */}</DrawerBody>
</Drawer>
```

### Inline preview

`preview` renders the panel inline in its parent rather than pinned to the viewport, ignoring `open`. It exists for this documentation playground and Storybook — not for production layouts.

```tsx
<Drawer preview>{/* ... */}</Drawer>
```

## Accessibility

- The panel renders `role="dialog"`. `DrawerHeader` registers its title element automatically, so `aria-labelledby` is wired for you. Pass `aria-label` on `Drawer` only when there is no visible heading.
- **Focus** — on open, focus moves to the close button, falling back to the first focusable element. On close, focus returns to whatever triggered the Drawer, so keyboard users are never dropped at `<body>`.
- **No focus trap.** Tab moves out of the panel and into the page behind it. This is correct for the non-blocking DFC pattern. If you are building a blocking ACGR-style Drawer, the page must add the trap and mark the app shell `inert` — the component will not do it for you.
- **Escape** closes the Drawer by default. Set `closeOnEscape={false}` for a non-blocking panel where `Esc` would fight a page-level shortcut, but keep the × button in that case.
- The × button carries `aria-label="Close drawer"` and a 32 × 32 px hit area, clearing the WCAG 2.5.8 minimum for a 16 px icon.
- The slide animates `transform` only, so it respects compositing and does not trigger layout on open.
