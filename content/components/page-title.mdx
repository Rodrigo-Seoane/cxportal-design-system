## Overview

Page Title is the primary visual anchor for any content page. It displays the page name in a large heading (plain dark neutral, not a brand color) alongside an optional subtitle and status chip. The right side is a composable slot where consumers can pass buttons, search bars, tabs, or any other page-level controls.

The component was simplified from three rigid variants to a single composable pattern. Figma's own Usage doc marks the **Instance Switcher** anatomy piece `[Deprecated]` — that's the only deprecated piece. The **Metadata Section** (KB-details variant: version, dates, associations) is a separate, still-live anatomy option in Figma's docs that this component doesn't implement — see Open questions below, not the same thing as the deprecated Instance Switcher.

## When to use

- At the top of every content page to identify the current context.
- When a page represents a categorized or classified record — enable `showChip` to display a status label.
- When page-level actions (edit, delete) or controls (search, role tabs) need to be accessible from the header.

## When not to use

- Do not use Page Title for section headers within the page content. Use H3/H4 headings instead.
- Do not use in modals, drawers, or side panels.

## Anatomy

- **Title** — 28px, weight 400, `#1d1d1d` (plain dark neutral, not a brand color). Always present.
- **Subtitle** *(optional)* — 12px, weight 400, `#8d8d8d` (muted secondary text). Descriptive one-liner below the title.
- **Chip** *(optional)* — Info pill with a leading icon, `#d6e2f5` background, 10px semibold text, border-radius 8px. Controlled by `showChip` prop.
- **Actions slot** *(optional)* — Right-aligned composable area, bottom-aligned with the title block. Consumers pass any ReactNode (ghost buttons, search inputs, tab groups, etc.).

## Do's & Don'ts

<DosDonts>
  <Do description="Keep the title to the page or record name — one to four words. Users scan it to confirm they're in the right place." />
  <Dont description="Put navigational cues (breadcrumbs, back arrows) inside the PageTitle component. Those belong above it in the layout hierarchy — confirmed by Figma's own Usage Anatomy list, which never mentions a breadcrumb piece even though the pulled 'Open Page Title' example frame shows one stacked above the title for illustration. Use the Open Page Title component for that composition instead of hand-stacking Breadcrumb and PageTitle yourself." />
</DosDonts>

<DosDonts>
  <Do description="Limit control actions to 2–3 primary operations. Secondary actions should be positioned within the page content." />
  <Dont description="Overcrowd the component with too many actions or metadata fields — it should establish hierarchy, not serve as a toolbar." />
</DosDonts>

## Accessibility

- The title renders as an `<h1>` — there should be only one PageTitle per page, and it should be the page's single top-level heading. **Resolved (2026-09-10):** Figma's own Usage doc says the page title "should be the first heading element on the page for screen reader navigation," which argues for `<h1>`; the app now follows that. The three routes that previously rendered their own literal `<h1>` for a record name alongside this component's title (`access-management/roles/[roleId]`, `users/[userId]`, `companies/[companyId]`, via a shared layout) had those demoted to `<h2>` to avoid duplicate top-level headings.
- The chip is decorative text inside a `<span>`; if dismissible, the dismiss button has an `aria-label`.
- Actions passed via the `actions` slot should be accessible buttons or links with visible labels.
- Use chips to indicate content type or status only when the categorization aids understanding — they should not be the only method of conveying critical information.
