## Overview

Collapsible Filters is a persistent side panel that lives to the left of a data table or list view. In its collapsed state it takes up minimal space — a single icon with an optional active-count badge. Expanding it reveals one or more filter controls. The transition between states is animated so the content area reflows smoothly.

The component is currently used in the Knowledge Management list view, where it drives Knowledge Base and Tag filtering.

## Design Principles

**Space efficiency first.** The panel collapses to 48 px so the content area is never crowded when filters are unused. Users who rely on filters expand once and keep the panel open.

**Always show filter state.** When the panel is collapsed but filters are active, a green count badge on the icon communicates that the current view is filtered — even before the panel is opened.

**Filtering is reversible.** A "Clear Filters" shortcut is always visible in the expanded header. Users never need to hunt for a way to reset.

## When to use

- Alongside data tables or list views that have more than one filterable dimension (e.g. by Knowledge Base *and* by Tag).
- When filter controls are secondary to the content — users need the filters occasionally, not on every visit.
- When the number of filter categories may grow over time (the panel scrolls internally).

## When not to use

- Do not use Collapsible Filters for simple single-dimension filtering — a standard `TableFilter` trigger inline with the table toolbar is sufficient.
- Do not use it for page-level search; use the search input in the top bar or toolbar instead.

## Anatomy

- **Panel container** — Fixed-width column (`48 px` collapsed / `240 px` expanded) with a `0.2 s ease` width transition. Bordered on the right.
- **Header row** — 48 px tall. Contains the toggle trigger and, when expanded, the "Filters" label and "Clear Filters" action.
  - **Collapsed state** — A secondary icon button (`SlidersHorizontalIcon`). If any filters are active a green circular badge shows the total active count.
  - **Expanded state** — A secondary icon button to collapse (same green-bordered style as the collapsed toggle), an 18 px "Filters" label, and a ghost "Clear Filters" link with an `XCircleIcon`.
- **Filter content area** — Visible only when expanded. Scrolls vertically. Contains one or more filter controls separated by 16 px gaps.
  - **TableFilter** — A full-width trigger that opens a portal checkbox dropdown. Shows a green pill with the active-selection count when filters are applied.
  - **Tags section** — A label row with a "New Tag" action, followed by `FilterTagItem` rows.
- **FilterTagItem** — A 32 px row with a custom checkbox, a color dot (solid or dashed), and the tag label. On hover or when the context menu is open, a `⋯` overflow button appears for Edit and Delete actions.

## Variants / States

| State | Width | Description |
|---|---|---|
| **Collapsed — no filters** | 48 px | Secondary icon button only |
| **Collapsed — filters active** | 48 px | Icon button with green count badge |
| **Expanded** | 240 px | Full filter panel with header, controls, and tag list |

## Guidelines

### DOs

- Always keep the panel in the leftmost column of a data layout — it pairs with the table's left edge.
- Show the active count badge on the collapsed icon whenever at least one filter is selected. Users need to know the view is filtered even when the panel is closed.
- Use `TableFilter` (portal checkbox dropdown) for list-type filters like Knowledge Base. Use the tag list pattern for label-based filters that users may also create or manage.
- Keep filter sections to a maximum of 2–3 categories. More than that overwhelms the panel.

### DON'Ts

- Don't clear filters automatically when the panel is collapsed. Active filters persist across collapse/expand cycles.
- Don't place action buttons (Save, Apply) inside the panel — filter changes apply immediately.
- Don't use this component for temporary, session-only filter overlays. For those, use a Drawer.

## Code

### Basic usage

```tsx
import { CollapsibleFilters } from '@/components/ui/collapsible-filters'
import { TableFilter } from '@/components/ui/table-filter'

<CollapsibleFilters
  collapsed={collapsed}
  onToggleCollapsed={() => setCollapsed(v => !v)}
  activeCount={activeKBs.size}
  onClearFilters={() => setActiveKBs(new Set())}
>
  <TableFilter
    label="Knowledge Base"
    size="compact"
    active={activeKBs.size > 0}
    count={activeKBs.size}
    onClick={openKbDropdown}
  />
</CollapsibleFilters>
```

### Tags section

```tsx
import { FilterTagItem } from '@/components/ui/collapsible-filters'

<div>
  <div style={{ fontSize: 18, color: 'var(--neutral-800)', marginBottom: 8 }}>Tags</div>
  <FilterTagItem
    label="status: Archived"
    dotColor="var(--info-100)"
    checked={activeTags.has('status:Archived')}
    onToggle={() => toggleTag('status:Archived')}
    onEdit={() => editTag('status:Archived')}
    onDelete={() => deleteTag('status:Archived')}
  />
</div>
```

### Collapsed with active count badge

Pass `activeCount` — the badge renders automatically whenever it's greater than 0 while `collapsed` is `true`. No separate prop toggles it.

### Props

```tsx
interface CollapsibleFiltersProps {
  collapsed: boolean               // controlled — persists across cycles per Figma's own principle
  onToggleCollapsed: () => void
  activeCount?: number             // drives the collapsed-state badge
  onClearFilters?: () => void      // omit to hide the "Clear Filters" link
  children?: ReactNode             // compose TableFilter / a Tags section / etc.
}

interface FilterTagItemProps {
  label: string
  dotColor: string                 // caller-supplied — tag colors are per-tag data
  dotDashed?: boolean
  checked?: boolean
  onToggle?: () => void
  onEdit?: () => void
  onDelete?: () => void
}
```

## Accessibility

- The toggle button in both collapsed and expanded states must have a descriptive `title` attribute (`"Expand filters"` / `"Collapse filters"`).
- When collapsed, the active-count badge is a decorative overlay on the icon button — provide an `aria-label` on the button that includes the count (e.g. `"Expand filters — 3 active"`).
- Tag color dots are purely visual — tag meaning must never be conveyed by color alone. The text label is always required.
- Filter changes apply immediately; no explicit Apply button means no confirmation step is needed. Screen readers should announce the updated result count via a live region on the list it filters.

## Open Questions

- **Figma's own component has no badge variant.** The pulled `CollapsibleFilters` component (`2212-5926`) only exposes `collapsed` and a `filterRows` demo count (2–5) — there's no modeled "collapsed with badge" variant at all. The badge is real and correctly documented in Principles/Usage, and a real, shipped reference implementation exists (`app/sandbox/collapsible-filter/page.tsx`, the Knowledge Management list view), so it was built to match those — but it's a gap in the Figma component's own variant coverage, not something to resolve by editing Figma.
- **The real reference implementation itself has a drift from the live component.** `app/sandbox/collapsible-filter/page.tsx`'s `FilterPanel` uses `variant="form-controls"` (a gray border) for the expanded-state collapse-toggle button, but Figma's own pulled component shows an identical green-bordered `secondary`-style button for both the collapsed and expanded toggles. Built to match the live component (`variant="secondary"` for both) rather than copy the sandbox's own inconsistency.
- **Doc's own stale token values, not followed:** Figma's Usage doc token table lists `--content-action/primary/default` as `#4285f4` (a pre-rebrand blue) even though the live pulled component renders "Clear Filters" in green (`#3a8015`) — the same pre-rebrand-blue stale-doc-value pattern found elsewhere in this audit. It also references `--content-action/secondary` (`#3264b8`, blue) and `--border/subtle` (`#eff1f3`) — neither token exists in this codebase at all, and the live component's own real colors (green "Clear Filters"/"New Tag" text, `#efefef` borders) don't match either. Documented above using the real, existing token names instead.
- **`--text-body-secondary` reinforces a second cross-cutting token-value gap.** Figma's Usage doc gives `#7a828c` for this exact spot (inactive icon color); this codebase's `--text-body-secondary` (`--neutral-400`) resolves to `#8d8d8d` instead. This is the same exact hex substitution (`#8d8d8d` instead of `#7a828c`) already flagged on Instance Card's `--border-color-surface-active-secondary-hover` — corroborating evidence that `--neutral-400`'s raw value itself may be wrong site-wide, not just one alias. Not changed here (blast radius, needs a designer call) — see `HANDOFF-PROMPT.md`.
- **Non-portal overflow menu.** `FilterTagItem`'s Edit/Delete menu is positioned `absolute` within the row rather than portal-rendered like the sandbox's `createPortal` version — a deliberate simplification, not a bug. `TableFilter`'s own dropdown (Anatomy item 6) isn't built into this component either; it's a trigger only, matching the already-shipped standalone `TableFilter` component's own scope.
- **"Blue" is leftover pre-rebrand terminology.** Figma's own Principles/Anatomy/Variants prose calls the active-count badge and TableFilter's count pill "blue" four separate times, but every real rendering — the pulled component's screenshot, the live sandbox implementation, and the doc's own Token Reference table — is green. Same naming-vs-value drift category as Metric Tiles' "Blue" surface rendering gray and Top Bar's purple-vs-green accent elsewhere in this audit. Corrected to "green" above rather than quoted verbatim.
